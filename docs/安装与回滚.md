## 装上之后**第一次启动会做什么**

1. 把 `~/.dsh/bili-duty/` **整体改名**成 `~/.dsh/bili/`（rename，不复制，连 `.venv` 一起走）
2. 老配置留底成 `~/.dsh/bili/config.legacy.json`，再写一份新形状的 `config.json`
3. 老位置留一个 `~/.dsh/bili-duty/MOVED.md` 说明
4. 写 `.migrated-v1` —— 之后每次启动只看这个标记，**不会重复搬**
5. 老配置里的**绝对路径**（主要是 `run.pythonPath` 指的 `.venv`）会跟着改到新家 ——
   不改的话升级后第一轮 MCP 直接 `spawn ...\bili-duty\.venv\... ENOENT`（2026-10-22 真机撞到过）

然后重启 DSH。

## pnpm 那件事

这台机器上**没有全局 pnpm**，而 `dsh plugin ...` 内部要调它。这次是用 corepack 临时搭了个壳：

```
.tmp\bin\pnpm.cmd   →  corepack pnpm %*
```
（`.tmp/` 在 `.gitignore` 里，不进仓库）

以后要再装插件，二选一：
- 把 `D:\Documents\Dsh Space\dsh-bili\.tmp\bin` 加进 PATH；
- 或者装个正经的 pnpm：`corepack enable`，之后 `pnpm` 就能直接用了。

## 重启后先看这四处

1. **设置页还在不在** —— 「设置 → B站鱼娘」能打开，顶部版本徽章显示 `2.1.0`
2. **家目录搬没搬** —— `~/.dsh/bili/` 出现、`~/.dsh/bili-duty/` 里只剩 `MOVED.md`
3. **日志里搜「搬进来」** —— `~/.dsh/bili/duty.log` 里会补写「搬进来：config.json」「路径已改到新家：…」之类。
   ⚠️ 别只盯文件开头：duty.log 是**累加**的（旧内容在前）。桌面版的后端日志
   `%APPDATA%\dsh-desktop\logs\backend-<启动时间>.log` 里也有同一份原始输出。
4. **跑一轮之后** —— 日志里那行是 `常驻会话 mode=queue` 还是 `dsh --profile headless`：
   - `mode=queue` ⇒ M3 常驻会话生效了（宿主工具她全能看见：日记 / 草稿 / 闸门）
   - `--profile headless` ⇒ 退回了 spawn（`sessionController` 没拿到），功能少一块但能跑
