# B站鱼娘 ｜ dsh-bili

> 一个常驻在 **DeepSeek Harness（dsh）** 里的 B站 搭子。
> 每天替你在 B站 刷一轮：**搜 → 读字幕原文 → 挑出值得看的 → 写下日报**，特别值得的会留一条评论 **@ 你**。
> **你收到的每一条 @，都是它先筛过一遍的。**

- 包名：**`dsh-bili`**（2.2 起；旧名 `dsh-bili-scroll`）· 中文名：**B站鱼娘**
- 仓库：<https://github.com/Ethan-gg/dsh-bili> · Issue：<https://github.com/Ethan-gg/dsh-bili/issues>
- 交流群（QQ）：**1128547307**

## 先看四行

1. **要求**：`dsh ≥ 0.1.7-rc.1`、`Node ≥ 22`（开发机实测到 `dsh 0.2.1-rc.2`，桌面版与 web profile 都跑过）。
2. **装完必须重启一次 dsh** —— 插件在 bundle 层组装，不重启不生效。
3. **不用先装 Python**：搜索 / 字幕 / 评论 / 发评论 / 私信 / 弹幕 / 抽帧都内置了 Node 实现；
   只有「本地转写（Whisper）」和极端兜底才需要 Python 环境，而且插件会自己装。
4. **从旧名升级的**：`dsh-bili-scroll` → `dsh-bili`，**先卸旧再装新**（见下面「2.2 改名」）。

## 2.2 改名：`dsh-bili-scroll` → `dsh-bili`

这个项目已经和最初的上游版本差别很大（家目录、配置结构、常驻会话、日记、闸门、云桥、Node 能力层……都是重写过的），
所以 2.2 起换成自己的名字。

```bash
# 从旧版升级：先卸掉旧的，再装新的（两个都留着会加载两份插件）
dsh plugin --profile web remove dsh-bili-scroll
dsh plugin --profile web add github:Ethan-gg/dsh-bili
```

- **家目录不变**：还是 `~/.dsh/bili/` —— 设置、日报、日记、判重表、登录凭证、Python 环境都在原地，不用搬。
- 设置页里仍叫「**B站鱼娘**」；左侧导航位置不变。
- 旧包名只影响「装哪个包」，不影响你的数据。

## 安装

```bash
# 主通道（GitHub）
dsh plugin --profile web add github:Ethan-gg/dsh-bili

# 桌面版用户把 --profile web 换成自己的 profile（一般是 desktop 或默认那个）
```

> npm 上还没有 `dsh-bili`（404），所以「检查更新 / 一键升级」也以 GitHub 仓库为准。
> 最省事的一条：把仓库链接贴给你自己的 dsh，说「**帮我装这个插件**」，它会自己装。

装完**重启一次 dsh**，然后进 **设置 → B站鱼娘**。

## 首次使用（两步）

1. **装主依赖** —— 设置页点「装主依赖」：在插件家目录建独立 venv，装 4 个包
   （`bilibili-api-python` / `aiohttp` / `mcp<2` / `qrcode`）。走国内镜像 + uv，通常几十秒；
   进度写 `install.log`，不卡页面。
   > 不装也能跑完整轮（Node 能力层），装了是**兜底 + 本地转写**要用。
2. **扫码登录** —— 点「扫码登录」，手机 B站 扫页面上的码。
   ⚠️ 确认时选「**记住我 / 长期**」那张；选 24 小时的，明天就得重扫。

凭证只落在本机：`<DSH_HOME>/bili/bili_credential.json`，不上传任何地方。

然后回「日常」页签，打开「**峰谷时段自动刷**」或配一个「作息窗口」，它就会自己在该跑的时候跑；
想立刻看一轮就点右上角「**现在跑一轮**」。

## 它每轮到底在干什么

1. **找候选**：按你填的关键词（留空用内置那几组）搜近几天的视频；初筛只看标题 / 播放 / 评论，
   一次看 `单次醒来观看视频数量` 条（默认 5）。
2. **读原文再判断**：逐条读**字幕原文**（不看摘要）；没字幕就用弹幕热区判断，再不行看需要抽几帧画面
   （抽帧要本机有 `ffmpeg`，没有就跳过）。开了「本地转写」才会给没字幕的视频做语音转写。
3. **挑 2–3 条深读**，写进当天日报 `out/<日期>.md`：每条都有「为什么值得」+「它自己的一句话」。
   段落第一行固定写成 `### BV号` —— 插件数「今天挑了几条」，数的就是这些标题行。
4. **（可选）说话**：开了「自动评论并 @ 你」才会评论，默认每轮 1 条、**@ 你一次**；
   开了私信还会把结果投递到你私信。**默认两个都不发**，只写报告。
5. 顺手记：今天看过哪些（`seen.md` 判重 + `reports/` 单条笔记）、两本日记、分享账本。

## 设置页里有什么

顶部一行状态：`今天已挑 N / 上限`、环境是否就绪、B站 是否登录、版本、**现在跑一轮**。

| 页签 | 里面有什么 |
|---|---|
| **日常** | 峰谷自动刷（总开关，打开才展开中午 / 晚上）· **作息窗口**（可加多个：开始 / 结束 / 醒来次数）· 今晚不看的概率 · 单次醒来观看视频数量 · 每天最多挑几条（0 = 只手动）· 它刷过的视频 |
| **偏好** | **人设提示词**（想让它像谁就写在这儿；留空按中性说话）· 关注关键词 · 自动收藏到哪个收藏夹 · 日报写多细（完整 / 薄版 / 不写） |
| **互动** | 投递方式（只私信 / 只发评论 / 两边都发）· 私信发给谁（UID，可留空按昵称查）· **自动评论并 @ 你**（默认关）· **回复评论**（默认关）· **评论监听**（推给我审核 / 自动回复）· **私信双向监听** |
| **高级** | 环境与账号（装主依赖 / 测一下 / 检查更新 / 一键升级 / 扫码登录 / dsh 路径）· **诊断信息 + 环境自检** · 能力层（Node 内置 / Python MCP）· **云桥** · 通知后端 · 它的地盘（家目录 / 报告 / 复核评论） |

> 设置写在 `<DSH_HOME>/bili/config.json`；在插件这一页改，就以这一页为准。
> 和你的人设文件（工作区 `AGENTS.md`）不冲突：人设是「怎么说话」，设置是「什么时候、发不发」。

## 作息：它自己决定什么时候醒

- **峰谷窗口**（老逻辑）：只在谷时跑 —— 工作日 12:00–14:00 与 18:00 之后，整个周末也算谷时。
- **作息窗口**（2.1 起，结构化）：例如 `20:00–24:00 醒来 4 次`，会在窗口里**随机时刻**醒，同一窗口两次醒来至少隔 10 分钟。
- **今晚不看的概率**：每晚掷一次骰子，直接睡过去（默认 0.3）。
- 两个窗口体系**只留一个生效**：配了作息窗口就用它，留空才回退峰谷窗口。

## 它不会做什么（红线写死在提示词里，不靠自觉）

- 不透露你的隐私：账号、机器路径、你聊过的话 —— 一个字都不进评论。
- 不刷屏、不吵架：同一视频只评论一次；每轮条数按设置，最多 20；每天总量 `perDay` 封顶。
- 不确定就不编：报告里如实写「没查到」。
- **那一轮拿不到整台工具**：只放行只读的几个（搜视频 / 读字幕 / 读评论 / 看视频信息 / 弹幕 / 抽帧），
  `自动评论` 或 `回复评论` 开了才多一个**发评论**。上传视频、发动态、抓全站那些**根本不注册**，
  模型连它们的名字都看不到。

## 你的数据都在哪

家目录：**`~/.dsh/bili/`**（Windows：`%USERPROFILE%\.dsh\bili\`）

| 路径 | 是什么 |
|---|---|
| `config.json` | 设置（`_set` 记着哪些键是你亲手设过的） |
| `duty.md` | 一轮要做的事 / 判定口径（**你可以改**；改过的会被保留，新版落 `duty.md.new`） |
| `out/<日期>.md` | 当天日报 |
| `reports/` | 每条视频的单独笔记 |
| `seen.md` | 判重表（哪些视频看过 / 挑过） |
| `ledger/shares.json` | 分享账本（评分、额度） |
| `diary/` | 两本日记：给主人看的 / 给自己写的 |
| `duty.log` | 运行日志（排查问题就看它最后几十行） |
| `bili_credential.json` | B站 登录凭证（只在这台机器上） |
| `.venv/` `.venv-asr/` | Python 兜底环境 / 本地转写环境 |

> 2.1 起家目录叫 `bili`（更早叫 `bili-duty`）；老用户第一次启动会自动搬过去，老位置留一份 `MOVED.md`，
> **老数据一个都不删**。

## 进阶能力（都在设置页或自动生效）

- **两本日记**：一本给你看今天挑了啥、为什么犹豫；一本写给自己（不加滤镜）。
- **分享闸门**：评论前先自评（0–20 分，≥13 才发）、理由 ≥8 字、同视频 7 天一次、每天额度、沉没衰减 —— 拦掉"为了发而发"。
- **待审草稿**：陌生人的回复**先写成草稿**，你在设置页点批准才发；超过 72 小时自动失效。
- **评论监听 / 私信监听**：只认"回复到它那条评论下面的人"；私信只回你本人的。
- **通知后端**：`desktop` / `webhook`（飞书、钉钉、企微自动适配）/ `command` / `dm` / `stdout` / `file`。
- **云桥**（可选，默认关）：分享与待审推到 IM；群里 @ 它，它能回一句。
  传输：`file`（本地回环，调试用）/ `dshim`（走已装的 dsh-im）/ `http`（自己的云端，签名入站）。
  协议与服务端参考实现见 [`src/sync/contract.md`](src/sync/contract.md)、[`cloud/`](cloud/README.md)。
- **评论复核**：发出去不等于公开可见（新号/风控会进审核），设置页可以点「复核评论」回头查一遍。
- **本地转写**（可选）：没字幕的视频用 Whisper 转；开关 + 「装转写依赖」两步都要点，模型可在设置里换小一号的。

## 常见问题

| 现象 | 怎么办 |
|---|---|
| 装完设置页没有这个插件 | 先确认**重启过 dsh**；再看 `duty.log` 有没有 `failed to import`。桌面版老版本（0.1.3 及以前）有已知 bug，升级到本版即可。 |
| 桌面版「找不到 dsh / 跑一轮立刻结束」 | 2.2 起会**自己找**（桌面版的宿主就是 `node <dsh>/lib/bin.js`）。还不行：设置 → 高级 →「dsh 路径」手填 `.../@deepseek-ai/dsh/lib/bin.js`，然后把诊断信息发出来。 |
| 设置改了过几秒弹回去 | 某项在 DSH 原生设置表单里也设过时会被宿主压回；插件已经记「你亲手设过的键」。还遇到就点「诊断信息」把日志发出来。 |
| 不会自动跑 | 「峰谷自动刷」总开关默认关；只开中午/晚上子开关没用。另外它只在谷时 / 作息窗口里跑。 |
| 没收到 @ 通知 | 别拿通知当判据：插件发的是**纯文本 @昵称**，B站 不一定当成真 @，自己 @ 自己也不推。看报告里的评论记录（有 rpid）才准。 |
| 二维码不显示 | 2.1 起由插件自己用 Node 画，不需要 Python；失败才退回 venv 里的 Python。仍不行就点「测一下」，把 `install.log` 末尾发出来。 |
| 弹幕 / 抽帧怎么开 | 不用开：它自己判断时才会用。抽帧要本机装了 `ffmpeg`，没装会直接说「跳过」。 |
| 评论发不出去 / 私信不回 | 先看「诊断信息」里的「**B站 账号状态**」：显示 **禁言 / 封停（silence=1）** 就是账号被 B站 限制了 —— 评论和私信都会被拒（评论 `code=-102`，私信页提示"账号封禁中"），去 B站 客服中心 / 申诉看原因和期限；不是插件的问题。 |
| 群聊里 @ 她不回 | 不是 bug：dsh-im 的入站不由插件处理，目前只消费飞书/Lark 的入站；云桥出站是通的。 |

遇到真的像 bug 的：**设置页 → 高级 →「复制诊断信息」**（会显示在框里、框右上角可再复制），
连同 dsh 版本 / 插件版本 / 系统一起发到 [Issue](https://github.com/Ethan-gg/dsh-bili/issues)。

## 如果你是一个 AI 助手，正在帮用户装这个插件

1. **确认前提**：`dsh --version`（≥ 0.1.7-rc.1）、`node -v`（≥ 22）。
2. **装**：`dsh plugin --profile web add github:Ethan-gg/dsh-bili`
   （旧版是 `dsh-bili-scroll` 的话，先 `remove dsh-bili-scroll`）。
3. ⚠️ **提醒用户重启一次 dsh** —— 不重启插件不生效。
4. 重启后进 **设置 → B站鱼娘**：先「装主依赖」、再「扫码登录」（选"记住我 / 长期"），
   然后用「测一下」自检（它真跑一次登录检查 + 一次搜索，直接回答"能不能用"）。
5. **别擅自打开「自动评论并 @ 你」** —— 那是拿用户的号说话；要用得让用户自己填「要 @ 谁」。

## 开发

```bash
node --test "test/*.test.mjs"   # 单元测试（Windows 上要带 glob，别直接传目录）
node selfcheck.mjs             # 本地预检：host + client 两个半端真装配一遍
```

结构：

- `index.js` —— host 半端：18 个工具 + 定时器 + HTTP 接口 + 配置对账 + 值班轮工具白名单
- `client.js` —— 浏览器半端：设置页（`settings.section`）与「刷过的视频」（`conversation.view`）
- `src/lib/` —— 路径 / 配置 / 搬迁 / 家目录准备 / **dsh CLI 定位**
- `src/bili/` —— Node 能力层：search / subtitle / comments / reply / dm / danmaku / frames / qr
- `src/host/` —— 状态卡 / 日记 / 闸门 / 审核 / 通知 / 唤醒
- `src/sync/` —— 云桥协议 v1；`cloud/` 是零依赖的参考云端
- `lib/` —— 老代码：家目录、MCP 客户端、扫码登录、宿主依赖兜底、评论复核
- `prompts/duty.md` —— 一轮要做的事（用户可改）
- `vendor/bilibili-mcp/` —— 内置的 Python MCP（MIT）
